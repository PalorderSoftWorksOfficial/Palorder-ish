# Security Policy

Do not publish secrets, tokens, or working exploits in public issues. Use the repository's private vulnerability reporting feature if enabled. Otherwise contact the repository owner privately through GitHub and request a secure reporting channel.

Include affected paths, impact, reproduction steps, and a proposed mitigation where possible.

Security-sensitive areas include runtime downloads and replacement, arbitrary command execution, package changes, and preservation of user configuration. Never put passwords, API tokens, or private keys in settings or issue reports.
